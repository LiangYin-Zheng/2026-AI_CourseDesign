# 肥胖风险预测系统项目需求

## 背景与目标

本项目服务于《人工智能综合实践》课程设计。目标是在真实读取仓库数据的基础上，形成从需求、数据、建模、手写算法、统一评估到交互展示和课程报告的完整工程链路，并保留可复现证据。系统输出是课程模型预测，不是医疗诊断。

## 功能需求

### FR-01 数据读取与质量检查

- 从配置路径读取 CSV，验证文件存在性、编码、表头、目标列、字段类型和空数据。
- 报告行列数、缺失、重复、唯一值、类别分布、数值范围和潜在异常。
- 原始数据只读，处理结果写入独立目录。

### FR-02 清洗、划分与预处理

- 清洗规则必须由实际检查结果驱动，并保留前后记录。
- 使用固定随机种子和目标分层，形成训练、验证、测试三部分。
- 只在训练数据上拟合编码器和标准化器；以 `Pipeline`/`ColumnTransformer` 串联预处理与 sklearn 模型。

### FR-03 探索性分析

- 对实际数值特征（至少 Age、Height、Weight）完成单变量分布与异常值分析。
- 完成它们与肥胖等级的双变量分析，以及多个特征联合的多变量分析。
- 生成数值特征相关性热力图、目标类别分布、箱线图等，并为每幅图提供数据依据与文字解释。

### FR-04 sklearn 分类

- 实现 `LogisticRegression` 和 `MLPClassifier` 基线。
- 使用验证集或仅在训练折上的交叉验证优化参数，测试集只在最终锁定方案后评估一次。
- 保存配置、模型/预处理器、指标、混淆矩阵、分类报告、耗时和运行日志。

### FR-05 Python/NumPy 手写算法

- 实现多分类逻辑回归：Softmax、交叉熵、梯度下降、正则化、训练记录、预测和概率。
- 实现前馈神经网络：隐藏层、激活、Softmax、前向/反向传播、Batch/Epoch、更新、训练记录、预测和概率。
- 与 sklearn 使用同一划分和统一评估接口，不得用 sklearn 分类器替代核心计算。

### FR-06 统一评估与比较

- 每个模型输出 Accuracy、每类 Precision/Recall/F1、macro avg、weighted avg、分类报告和混淆矩阵。
- 比较训练时间、推理时间、模型复杂度、优缺点和适用场景；性能优化前后均保留结果。
- 结果分析必须区分观察事实与解释假设，不夸大因果关系。

### FR-07 交互系统

- 首页：简介、数据概况、模型状态、入口、推荐模型。
- 数据分析页：规模、质量、分布、箱线图、热力图和解释。
- 模型训练页：实现类型/算法/参数选择、进度、状态、耗时、曲线、指标、矩阵和预测模型选择。
- 预测页：只使用经确认可人工输入的实际字段，验证必填、数值范围和类别选项，输出类别概率、最高概率、模型和非医疗声明。
- 比较页：统一比较四类模型。

### FR-08 课程过程材料

- 每日维护实习日志；第 19、20、21 周周一制作不超过 5 分钟的周报 PPT。
- 最终按指定模板独立完成不少于 10 页、5,000 字、至少 4 个一级标题、至少 5 篇参考文献的报告。

## 非功能需求

- **可复现性**：固定随机种子；记录数据哈希、配置、依赖、运行环境和结果路径。
- **可测试性**：配置、路径、数据划分、预处理、防泄漏、指标和手写梯度/预测等关键模块有自动化测试。
- **兼容性**：只支持指定 macOS/Apple M5/Conda Python 3.10 环境；新增依赖需验证兼容。
- **可维护性**：YAML 配置、`pathlib`、`logging`、中文注释、类型标注、单一职责、清晰异常。
- **可用性**：界面层级清楚、参数解释明确、错误可恢复、训练状态可见。
- **性能**：20,758 行规模下，四模型训练和推理须能在课程设备上完成；具体时间以实测记录，不预设虚假阈值。
- **安全与伦理**：不存储凭据或隐私；不将结果表述为诊断；报告数据局限和误判风险。

## 数据需求

- 唯一事实源为 `data/obesity_level.csv`；目标暂定且实际确认为 `0be1dad`。
- `id` 默认不进入模型；最终排除决定须由数据理解与防泄漏审查确认。
- 数值存储不等于特征语义：0/1 列应作为二元类别候选；字符串列按类别处理；连续/序数属性的处理方式由阶段三实验确定。
- 任何友好字段名、单位、取值含义映射都应配置化并注明来源，不能改写原始 CSV。

## 测试需求

- 单元测试：配置校验、路径、数学函数、模型 API、指标结构。
- 数据测试：schema、目标类别、分层比例、三集合互斥、只在训练集拟合。
- 集成测试：从配置到训练/评估/保存的最小链路；四模型统一接口。
- UI 测试：合法/非法输入、训练状态、结果展示、模型切换和非医疗提示。
- 回归检查：固定种子下数据索引和关键结果结构稳定；不要求跨库版本浮点值逐位相等。

## 最终交付与项目边界

必须交付源代码、配置、测试、依赖说明、数据理解与图表、四类模型及统一评估、交互界面、运行说明、日志、PPT、报告和验收证据。当前阶段仅交付需求与规划文档；不清洗数据、不训练模型、不实现算法或界面。范围详见 `03_project_scope.md`。
