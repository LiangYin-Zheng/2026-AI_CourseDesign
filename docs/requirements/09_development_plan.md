# 五阶段开发计划

## 计划控制

- 顺序固定为阶段 1→2→3→4→5；每阶段按 `08_acceptance_criteria.md` 通过门禁后再开始下一阶段。
- 每个推荐提交点只提交强相关文件，并使用中文 Conventional Commit 双 `-m`。
- 时间安排以课程第 19、20、21 周汇报节点为外部约束；具体自然日由教师日程和实际进度确认。

## 阶段一：需求分析与项目文档

- **目标**：建立可信事实基线和完整工程规划。
- **输入**：课程计划 PDF、报告/日志 DOC 模板、项目执行说明、原始 CSV、Git/环境状态。
- **任务**：审查来源；只读统计数据；建立 AGENTS、需求、追踪、范围、字典、路线、模块、验收、Issue、风险和交付清单。
- **输出**：根目录 `AGENTS.md` 与 `docs/requirements/00`–`12`。
- **完成条件**：A1-01 至 A1-10 全部通过。
- **风险**：字段说明缺失、模板规则冲突、AGENTS 原被忽略。
- **前置依赖**：正确仓库和 Python 3.10 环境。
- **推荐提交点**：长期上下文；需求/范围；数据理解；技术设计；验收/开发计划；Issue/风险/交付。

## 阶段二：工程初始化（已完成）

- **目标**：构建不训练模型的最小可运行、可测试骨架。
- **输入**：阶段一文档、实际 schema、环境依赖清单。
- **任务**：建立最小 Python 包；建立 YAML 配置；实现配置读取与校验；实现路径解析与原始数据保护；建立简单运行入口；建立配置和路径测试；编写 README。
- **输出**：`config/default.yaml`、四模块 `src/obesity_risk/`、`tests/test_config.py`、`tests/test_paths.py`、`pyproject.toml` 和 README。
- **完成条件**：A2-01 至 A2-05 全部通过；无模型、处理数据或 UI 正式实现。
- **风险**：PyYAML/pytest 版本兼容，路径配置错误导致越界或覆盖原始数据。
- **前置依赖**：阶段一通过；字段/路径待确认项得到可配置处理。
- **推荐提交点**：最小包/依赖；YAML 与配置校验；路径保护与测试；简单入口/README。

## 阶段三：sklearn 完整版本

- **目标**：完成端到端 sklearn 数据、EDA、两模型、优化和最终评估。
- **输入**：工程骨架、原始 CSV、配置、验收标准。
- **任务**：读取/质量/清洗；根据实验记录需要引入 `logging`；分层三分；训练拟合预处理；EDA；LR；MLP；基线；验证集优化；锁定后测试；保存产物和分析。
- **输出**：处理规则/索引、图表、两类模型、指标、日志、实验元数据、测试。
- **完成条件**：A3-01 至 A3-07 全部通过；测试集只用于最终一次评估。
- **风险**：目标构造泄漏、稀有输入类别、MLP 收敛、过拟合和项目运行环境兼容性。
- **前置依赖**：阶段二通过；字段语义尽量确认；不得依赖手写或 UI。
- **推荐提交点**：读取/质量；清洗/划分；预处理；EDA；LR；MLP；评估；优化；产物保存。

## 阶段四：Python/NumPy 手写版本

- **目标**：以可验证数学实现复现两类多分类器并公平对比。
- **输入**：阶段三固定划分、预处理数据、标签映射和统一评估协议。
- **任务**：稳定数学函数；Softmax 回归及梯度；前馈网络及反向传播；小数据和有限差分测试；训练；优化；四模型对比。
- **输出**：手写模型源码、损失曲线、测试、模型/指标产物、统一对比表。
- **完成条件**：A4-01 至 A4-07 全部通过。
- **风险**：溢出、梯度错误、训练速度、损失不收敛、比较口径变化。
- **前置依赖**：阶段三全部通过并冻结划分协议。
- **推荐提交点**：数学函数；手写回归及测试；网络前向；反向传播及梯度检查；训练/评估；统一比较。

## 阶段五：交互界面与最终交付

- **目标**：将稳定核心能力集成为演示系统，完成全部课程材料。
- **输入**：四模型服务、分析/指标/产物、课程模板和过程日志。
- **任务**：选择兼容 UI 框架；应用服务；首页；分析；训练；预测；比较；集成/功能测试；日志/PPT/报告整理；复现验收。
- **输出**：五页面应用、测试、运行说明、日记、三次 PPT、模板报告、最终清单。
- **完成条件**：A5-01 至 A5-09 全部通过，无否决项。
- **风险**：长训练阻塞 UI、模型/输入 schema 不一致、展示口径错误、报告材料积累不足、5 分钟超时。
- **前置依赖**：阶段四通过；UI 框架经目标 Python 3.10 环境的最小试验确认。
- **推荐提交点**：UI 框架/服务；各页面分别提交；集成测试；日志材料；PPT；报告；最终文档。

## 推荐迭代节奏

1. 每个工作日开始前检查 AGENTS/Git/阶段；结束前写日志、运行相关测试并更新证据。
2. 每周汇报前冻结一份可运行状态，PPT 只报告真实完成项、结果、问题和下一周计划。
3. 每个模型先基线再优化；每个界面页面先服务测试再接 UI；每次提交前检查原始 CSV 哈希和 Git diff。
