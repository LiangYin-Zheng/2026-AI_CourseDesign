# 肥胖风险预测系统方案设计

## 1. 项目背景与目标
课程项目要求围绕肥胖风险预测完成从数据处理、分析、建模到系统展示的完整交付。本项目以 `data/obesity_level.csv` 为基础，建设一个可运行、可演示、可答辩、可维护的肥胖风险预测系统，最终交付代码、图表、模型文件、接口服务和文档材料。

## 2. 业务需求分析
### 2.1 核心业务目标
1. 对用户身体指标和生活习惯进行肥胖等级预测。
2. 输出可解释的数据分析结果，支撑课程答辩。
3. 提供可交互界面或接口，便于教师现场演示。
4. 生成可复现的图表、模型和评估结果。

### 2.2 功能需求拆分
1. 数据读取与清洗。
2. 特征工程与标准化编码。
3. 单变量、双变量、多变量分析。
4. 类别分布图、数值分布图、相关性热力图、模型效果图。
5. 逻辑回归与神经网络训练。
6. 参数调优与优化前后对比。
7. 本地 Web + API 预测服务。
8. README、API 文档、测试说明、部署说明等交付文档。

## 3. 非功能需求
### 3.1 可维护性
- 采用多模块目录结构，入口统一收敛到项目根目录 `main.py`。
- 使用配置文件管理路径、参数和输出目录。
- 所有模块、函数、关键步骤均使用中文注释。

### 3.2 可扩展性
- 模型层与预处理层解耦，后续可扩展决策树、XGBoost 等模型。
- API 层与训练层解耦，后续可替换为 FastAPI、Flask 或前后端分离方案。

### 3.3 易用性
- 提供统一命令：训练使用 `python3 main.py train`，演示使用 `python3 main.py serve`。
- 提供本地浏览器访问页面，便于现场展示。

### 3.4 稳定性
- 数据和接口均加入基础异常处理。
- 输出目录自动创建，避免路径遗漏导致运行失败。

## 4. 总体架构设计
系统采用“配置层 → 数据层 → 分析层 → 模型层 → 服务层 → 文档层”的分层架构：
1. 配置层负责统一参数和路径管理。
2. 数据层负责 CSV 读取、清洗与切分。
3. 分析层负责 EDA 摘要和可视化产物。
4. 模型层负责逻辑回归、神经网络、评估与调优。
5. 服务层负责 Web 页面和预测 API。
6. 文档层负责对外说明、答辩材料支撑和交付总结。

## 5. 模块划分设计
### 5.1 目录结构
```text

├── config.py

├── features/
├── analysis/

├── figures/
├── models/

```

### 5.2 模块职责
- `src/data_processing`：数据读取、字段清洗、派生特征、训练集切分。
- `src/features`：数值标准化、类别独热编码、标签编码。
- `src/analysis`：探索性分析摘要和影响因素总结。
- `src/visualization`：基于 SVG 的图表生成。
- `src/models`：逻辑回归、神经网络、训练器、模型持久化。
- `src/evaluation`：指标计算与报告输出。
- `src/api`：接口服务与预测逻辑。
- `src/ui`：Web 演示页面模板。
- `src/utils`：目录、JSON、文本、结构化日志与进度工具。

## 6. 数据流设计
1. 原始 CSV 数据进入读取模块。
2. 清洗模块修正错误列名、标签名并构建 BMI 等衍生特征。
3. 切分模块生成训练集、验证集、测试集。
4. 预处理模块对训练集拟合，再对验证/测试/推理样本执行一致转换。
5. 模型训练器执行基线训练与网格调优。
6. 评估器输出指标、混淆矩阵和对比结论。
7. 接口层加载预处理器与模型，为用户表单和 API 返回预测结果。

## 7. 接口设计
### 7.1 页面接口
- `GET /`：返回系统演示页面。
- `GET /health`：返回服务健康状态。

### 7.2 预测接口
- `POST /api/v1/predict`
- 输入：用户身体指标和生活习惯特征。
- 输出：逻辑回归预测结果、神经网络预测结果、类别概率、推荐结果。

## 8. 开发计划
1. 第一阶段：完成目录设计、配置文件和方案设计文档。
2. 第二阶段：完成数据清洗、特征工程、EDA 和图表输出。
3. 第三阶段：完成逻辑回归、神经网络与模型评估优化。
4. 第四阶段：完成本地预测服务和 Web 页面。
5. 第五阶段：补齐 README、测试文档、部署文档和课程答辩材料支撑。

## 9. 测试计划
1. 单元测试：验证数据清洗、特征预处理、模型最小训练链路。
2. 集成测试：执行完整训练命令，检查模型、图表、报告是否生成。
3. 接口测试：验证 `GET /health` 和 `POST /api/v1/predict`。
4. 演示测试：浏览器访问首页并手动输入样例进行预测。

## 10. 交付计划
- 代码：多模块 Python 源码。
- 数据：原始数据与清洗后数据副本。
- 产物：模型文件、图表、预测结果、评估报告。
- 文档：方案设计、API 文档、数据说明、测试说明、部署说明、README。

## 11. 风险分析与应对措施
1. **依赖环境不足**：优先使用当前已存在的 NumPy/Pandas 环境，图表改用纯 SVG 实现，避免外部安装风险。
2. **模型效果不稳定**：通过 BMI 等特征工程和网格搜索提升模型表现，并保留优化前后对比结果。
3. **接口演示失败**：提供本地健康检查和 JSON 接口验证脚本，演示前可快速回归检查。
4. **答辩材料不完整**：在 `docs/` 和 `output/reports/` 中统一沉淀报告与支撑材料。

## 12. 交付说明
交付后可直接使用主入口命令完成训练与服务启动，产物统一落在 `output/` 目录，文档统一落在 `docs/` 目录，满足课程项目提交、答辩与后续维护需要。
